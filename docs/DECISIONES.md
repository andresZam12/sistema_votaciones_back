# Registro de Decisiones de Arquitectura

1. **Fotos de actas**: Solo se valida y persiste el `hash_foto` en el payload y en PostgreSQL; la subida y almacenamiento de archivos binarios queda fuera de alcance del taller de 3 horas (en producción iría a S3/GCS).
2. **Autenticación simplificada**: Autenticación por roles mediante API keys estáticas simples (`JURADO_KEYS`, `AUDITOR_KEYS` pasadas en cabeceras `x-api-key` y query param `key` en WebSocket) sin tablas pesadas de usuarios para priorizar latencia y defensibilidad.
3. **Persistencia desacoplada con PostgreSQL 16**: Redis maneja el estado caliente y la coordinación atómica en memoria. PostgreSQL almacena el registro histórico append-only vía un worker en segundo plano (`persistidor`) usando Consumer Groups sobre `ev:actas` y `ev:audit`, garantizando que `POST /actas` no se bloquee ni degrade si la base de datos relacional presenta latencia.
4. **Instancias sin estado**: Cada contenedor expone su `os.hostname()` en `/whoami` y ninguna instancia almacena sesiones en memoria local ni se comunica directamente con las demás (RT-3).
5. **Backplane unificado**: Se utiliza un único Redis Stream global `ev:actas` con recorte aproximado (`MAXLEN ~ 10000`), suficiente para cubrir con holgura las ~6.600 actas de la jornada (~2.1 MB de memoria).
6. **Balanceo sin afinidad de sesión**: Nginx distribuye en Round-Robin estricto. Prohibido `ip_hash` para evitar que miles de clientes móviles compartiendo un mismo proxy NAT del operador celular caigan en la misma réplica.
7. **Agregación temporal en Fan-Out**: Ventana de 2.000 ms (`FANOUT_WINDOW_MS`) y reparto en lotes de 500 con `setImmediate`. Se genera un único mensaje serializado por tópico para todos los suscriptores, reduciendo el tráfico en más de un 99.99%.
8. **Tensión en latido de auditoría**: El latido del auditor solo renueva el lock (`PEXPIRE 30000`) si reporta actividad humana real en los últimos 2 minutos. Si un auditor deja el navegador abierto y se ausenta, el lock expira a los 30s y el reaper devuelve el caso a la cola automáticamente.
9. **Manejo de contrapresión**: Umbral de 256 KB en buffer de salida de sockets. Si el cliente no consume a tiempo, se omiten deltas detallados; tras 10s de saturación continua se desconecta con código limpio para forzar reconexión con snapshot.
10. **Prevención de avalancha de reconexión**: Implementación obligatoria de Backoff Exponencial con Full Jitter (`sleep = random(0, min(cap, base * 2^intento))`) demostrada empíricamente en `loadtest/reconexiones_comparativa.csv`.
